# Git Hooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tracked git hooks that check the changed half of the app on every commit and run the full check (strict about skipped DB tests) on every push.

**Architecture:** Three bash files in a tracked `.githooks/` folder, enabled per clone with
`git config core.hooksPath .githooks`. `lib.sh` holds every check as a function; `pre-commit` and
`pre-push` only decide which functions to call and in which mode. Spec:
`docs/superpowers/specs/2026-10-21-git-hooks-design.md`.

**Tech Stack:** bash (Git for Windows' bundled bash / any Linux bash), CMake + Ninja (MSYS2 UCRT64),
GoogleTest output parsing with `sed`, npm/npx (tsc, vitest, vite).

## Global Constraints
- Hook scripts **must** have LF line endings (`core.autocrlf=true` on this machine), enforced by `.gitattributes`.
- Hook files committed executable (`git add --chmod=+x`).
- Server tests run via the `kinetiq_tests` binary directly, **not** `ctest`.
- Skipped server tests: pre-commit → **warn + allow**; pre-push → **block**. Detected from GoogleTest's
  summary line `[  SKIPPED ] N tests, listed below:` (verified 2026-10-21: binary exits 0 in this case).
- Hooks check the working tree, not the exact staged snapshot (no stashing).
- No Docker builds, formatters, linters or new dependencies.
- Simulate "Postgres unavailable" with `DB_PORT=1` (both `main.cpp` and `TestDb.cpp` read `DB_PORT`)
  so the running dev Postgres doesn't have to be stopped, except in Task 3's real-stop check.

**Interfaces:**

- [ ] **Step 3: Write `.githooks/lib.sh`**

```bash
# shellcheck shell=bash
# Shared helpers for .githooks/pre-commit and .githooks/pre-push.
# This file is SOURCED (". lib.sh"), never executed directly. The caller must
# set HOOK_NAME first; it prefixes every line we print.

# --- Environment -----------------------------------------------------------

# Hooks can be started from any directory; always work from the repo root.
REPO_ROOT="$(git rev-parse --show-toplevel)" || exit 1
cd "$REPO_ROOT" || exit 1

# The C++ toolchain (g++, cmake, ninja) lives in MSYS2 UCRT64 on Windows.
# The folder doesn't exist on Linux/CI, so this is a no-op there.
if [ -d /c/msys64/ucrt64/bin ]; then
  PATH="/c/msys64/ucrt64/bin:$PATH"
fi

# Each step writes its full output here; we only show it when a step fails.
LOG="$(mktemp)"
trap 'rm -f "$LOG"' EXIT

# Colors only when printing to a real terminal (not e.g. VS Code's git log).
if [ -t 1 ]; then
  RED=$'\033[31m'; YEL=$'\033[33m'; GRN=$'\033[32m'; RST=$'\033[0m'
else
  RED=''; YEL=''; GRN=''; RST=''
fi

# --- Output ----------------------------------------------------------------

say()  { printf '[%s] %s\n' "$HOOK_NAME" "$*"; }
warn() { printf '%s[%s] WARNING: %s%s\n' "$YEL" "$HOOK_NAME" "$*" "$RST"; }
fail() { printf '%s[%s] %s%s\n' "$RED" "$HOOK_NAME" "$*" "$RST" >&2; }

# run_step "<label>" <command> [args...]
# Runs the command with all output captured to $LOG and prints ONE status
# line with the elapsed time. On failure, prints the tail of the log so the
# real error is visible without scrolling through passing output.
run_step() {
  local label="$1"; shift
  local start=$SECONDS
  printf '[%s] %-36s ' "$HOOK_NAME" "$label"
  if "$@" >"$LOG" 2>&1; then
    printf '%sok%s (%ss)\n' "$GRN" "$RST" "$((SECONDS - start))"
  else
    printf '%sFAILED%s (%ss)\n' "$RED" "$RST" "$((SECONDS - start))"
    echo "----- last 40 lines of output -----"
    tail -n 40 "$LOG"
    echo "-----------------------------------"
    return 1
  fi
}

# --- Preconditions ---------------------------------------------------------

require_server_tools() {
  local tool
  for tool in cmake ninja g++; do
    if ! command -v "$tool" >/dev/null 2>&1; then
      fail "'$tool' not found. Install the MSYS2 UCRT64 toolchain (see README)"
      fail "and check that C:\\msys64\\ucrt64\\bin exists."
      return 1
    fi
  done
}

require_client_deps() {
  if [ ! -d Client/node_modules ]; then
    fail "Client/node_modules is missing. Run 'npm install' in Client/ first."
    return 1
  fi
}

# --- Server ----------------------------------------------------------------

# Small wrappers so run_step gets a single command. The ( ... ) subshell keeps
# the `cd` from leaking into the rest of the hook.
server_configure() { (cd Server && cmake --preset default); }
server_build()     { (cd Server && cmake --build --preset default); }
server_tests() {
  # .exe on Windows, no extension on Linux.
  if [ -f Server/build/kinetiq_tests.exe ]; then
    Server/build/kinetiq_tests.exe
  else
    Server/build/kinetiq_tests
  fi
}

# server_check warn|strict
# Builds the server and runs all its tests. DB integration tests SKIP (not
# fail) when Postgres is unreachable or a migration is broken, and the test
# binary still exits 0 -- so we read GoogleTest's summary line
# "[  SKIPPED ] N tests, listed below:" ourselves.
#   warn   -> print a warning, still succeed   (pre-commit)
#   strict -> treat skips as a failure         (pre-push)
server_check() {
  local mode="$1"
  require_server_tools || return 1

  # Fresh clone: no build folder configured yet.
  if [ ! -f Server/build/CMakeCache.txt ]; then
    run_step "Server: configure (first time)" server_configure || return 1
  fi
  run_step "Server: build" server_build || return 1
  run_step "Server: tests" server_tests || return 1

  local passed skipped
  passed="$(sed -n 's/^\[  PASSED  \] \([0-9][0-9]*\) test.*/\1/p' "$LOG" | head -n 1)"
  skipped="$(sed -n 's/^\[  SKIPPED \] \([0-9][0-9]*\) test.*/\1/p' "$LOG" | head -n 1)"
  say "  -> ${passed:-0} passed, ${skipped:-0} skipped"

  if [ "${skipped:-0}" -gt 0 ]; then
    local msg="${skipped} server test(s) were SKIPPED. Usually the DB tests: is Postgres running? (docker start kinetiq-postgres). A broken migration causes the same symptom."
    if [ "$mode" = strict ]; then
      fail "$msg"
      return 1
    fi
    warn "$msg"
  fi
}

# --- Client ----------------------------------------------------------------

client_typecheck() { (cd Client && npx tsc --noEmit); }
client_tests()     { (cd Client && npx vitest run); }
client_prod_build() { (cd Client && npm run build); }

client_check() {
  require_client_deps || return 1
  run_step "Client: type-check" client_typecheck || return 1
  run_step "Client: tests" client_tests || return 1
}

client_build() {
  require_client_deps || return 1
  run_step "Client: production build" client_prod_build
}
```

### Task 2: `pre-commit` hook + enable hooks

**Files:**
- Create: `.githooks/pre-commit`

**Interfaces:**
- Consumes: `say`, `fail`, `server_check warn`, `client_check` from `lib.sh` (Task 1).
- Produces: hooks enabled in this clone via `core.hooksPath`.

- [ ] **Step 1: Write `.githooks/pre-commit`**

```bash
#!/usr/bin/env bash
# Runs automatically on `git commit` (enable once per clone with
# `git config core.hooksPath .githooks`). Checks only the half of the app
# that has staged changes; docs-only commits run no checks.
# A non-zero exit cancels the commit.
# Emergency bypass (e.g. a deliberate TDD "red" commit): git commit --no-verify
HOOK_NAME=pre-commit
. "$(dirname "$0")/lib.sh"

staged="$(git diff --cached --name-only)"
server_changed=no
client_changed=no
if printf '%s\n' "$staged" | grep -q '^Server/'; then server_changed=yes; fi
if printf '%s\n' "$staged" | grep -q '^Client/'; then client_changed=yes; fi

if [ "$server_changed" = no ] && [ "$client_changed" = no ]; then
  say "no app code changed, skipping checks"
  exit 0
fi

status=0
if [ "$server_changed" = yes ]; then
  server_check warn || status=1
else
  say "Server unchanged -> skipped"
fi
if [ "$client_changed" = yes ]; then
  client_check || status=1
else
  say "Client unchanged -> skipped"
fi

if [ "$status" -ne 0 ]; then
  fail "commit blocked. Fix the failure above, or bypass with: git commit --no-verify"
fi
exit "$status"
```

```bash
#!/usr/bin/env bash
# Runs automatically on `git push`. Full check of BOTH halves regardless of
# what changed, and strict: skipped DB tests block the push, so nothing
# reaches GitHub unless all server tests really ran.
# Emergency bypass: git push --no-verify
HOOK_NAME=pre-push
. "$(dirname "$0")/lib.sh"

say "full check before push (server + client)"
status=0
server_check strict || status=1
client_check || status=1
client_build || status=1

if [ "$status" -ne 0 ]; then
  fail "push blocked. Fix the failure above, or bypass with: git push --no-verify"
fi
exit "$status"
```
